# Production Architecture Design: app-vibed-app-5

## Context

`app-vibed-app-5` is an Express 5 and React/Vite note-taking and summarization web application. The frontend allows users to enter notes, fetch notes list, trigger Gemini AI summaries, upload file attachments, view uploaded files, and export files as a zip archive. An administrative endpoint allows deleting notes using a timing-safe administrative bearer token.

The application is containerized via a multi-stage Dockerfile (`node:latest` builder, `node:24-slim` runner). To run reliably in a serverless production environment on Google Cloud, ephemeral local disk operations (`uploads/`) and in-memory note storage (`let notes = []`) must be externalized to managed Google Cloud services. Furthermore, Gemini AI summarization must transition from API key authentication to Vertex AI Application Default Credentials, and the CORS policy must permit traffic from the Cloud Run service origin.

## Architecture

The application runs on Google Cloud in project `vibe2prod-509620`, region `us-central1`.

- **Compute**: A single Cloud Run service (`app-vibed-app-5`) running the combined container image. It serves both the static Vite frontend from `/dist` and all backend API routes on port 3000.
- **Database**: Cloud Firestore Native database (`app-vibed-app-5`) in `us-central1`. The default project database is strictly avoided. Notes are persisted in a dedicated `notes` collection.
- **Object Storage**: Cloud Storage bucket (`app-vibed-app-5-uploads`) in `us-central1` for durable file storage, streaming downloads, and zip archive exports.
- **AI Summarization**: Vertex AI `gemini-3.8-flash` called via `@google/genai` using `vertexai: true` in the `global` location, authenticated via the Cloud Run runtime service account.
- **Secrets Management**: Secret Manager secret (`app-vibed-app-5-admin-token`) holding a 32-character random string generated by Terraform for the `ADMIN_TOKEN` environment variable.
- **Public Access**: Configured with `ingress = INGRESS_TRAFFIC_ALL` and `invoker_iam_disabled = true` to allow public traffic without violating the organizational policy forbidding `allUsers` IAM bindings.

## Data Flow

1. **Static Assets & Web UI**: The browser requests `/`, which Express serves from `/dist/index.html` and bundled React assets. Subsequent single-page app interactions call `/api/*`.
2. **Health Probes**: Cloud Run startup and liveness probes query `GET /api/health`. The route returns `{ status: "ok" }` instantly without hitting Firestore or external APIs.
3. **Notes Lifecycle**:
   - `GET /api/notes`: Express queries Firestore collection `notes` ordered by `id` ascending and returns the array of note documents.
   - `POST /api/notes`: Express validates payload `text`, assigns `id: Date.now()`, writes `{ id, text }` to `notes/{id}` in Firestore, and returns 201.
   - `DELETE /api/notes/:id`: Express verifies the incoming `x-admin-token` header against `process.env.ADMIN_TOKEN` using `crypto.timingSafeEqual`. Upon validation, it deletes document `notes/{id}` from Firestore and returns `{ ok: true }`.
4. **AI Summarization**:
   - `POST /api/summarize`: The client submits notes (or the server fetches current notes from Firestore if omitted). Express constructs the summarization prompt and invokes `@google/genai` Vertex AI client targeting `gemini-3.8-flash` in `global`. The generated text summary is returned as JSON `{ summary: response.text }`.
5. **File Attachments & Export**:
   - `POST /api/upload`: Multer processes file in memory (`multer.memoryStorage()`), generates a cryptographically random filename with sanitized extension, streams the buffer directly to `app-vibed-app-5-uploads`, and returns `{ name: filename }`.
   - `GET /api/files/:name`: Express validates the filename segment using `isSafePathSegment`, verifies object existence in Cloud Storage, and pipes the file stream directly to the response with matching MIME type.
   - `GET /api/export`: Express lists objects in `app-vibed-app-5-uploads`, pulls file buffers into an `AdmZip` instance, and sends the zipped payload with `Content-Type: application/zip` and sanitized attachment filename.
6. **Search**: `GET /search?q=...` sanitizes and escapes query inputs via `validator.escape` and returns safe HTML output.

## Security

- **Service Identity & Principle of Least Privilege**: Cloud Run executes under `vibe2prod-app-runtime@vibe2prod-509620.iam.gserviceaccount.com`. This identity already has `roles/aiplatform.user`. The service account is granted `roles/storage.objectViewer` and `roles/storage.objectCreator` on the bucket and `roles/secretmanager.secretAccessor` on the specific secret. Project-level datastore permissions are strictly constrained to `roles/datastore.user` with a CEL condition scoped only to the `app-vibed-app-5` database.
- **Network and Ingress**: Cloud Run enables `invoker_iam_disabled = true` with `INGRESS_TRAFFIC_ALL`, satisfying the org policy prohibition on `allUsers` IAM bindings while enabling public access.
- **Secrets**: The `ADMIN_TOKEN` is generated dynamically by Terraform (`random_password`) and injected via Cloud Run's secret volume environment mapping. No raw secrets exist in plaintext configuration or source code.
- **Storage Security**: Cloud Storage enforces `uniform_bucket_level_access = true` and `public_access_prevention = enforced`. Files are never exposed via public bucket URLs; all access is mediated and validated through the Express backend.
- **Application Layer**: Express implements `helmet()` for secure HTTP headers, size limits on JSON body (1MB) and uploads (5MB), input validation using `validator`, and timing-safe equality checks on administrative authentication headers.

## Cost Drivers

- **Cloud Run Compute**: CPU (1 vCPU) and Memory (512MiB) billed during active request processing. With `min_instance_count = 0`, instances scale to zero during idle periods, incurring no compute charges when inactive. Request concurrency is set to 80.
- **Cloud Firestore**: Billed by document operations (reads, writes, deletes) and stored data volume. For demo workloads, storage remains under 0.1 GB and operations remain well within low-volume tiers.
- **Cloud Storage**: Billed by gigabyte-months stored (~1.5 GB Standard class) and Class A operations (uploads, bucket list) and Class B operations (file streams). An automatic 30-day lifecycle rule purges old demo files to cap long-term storage growth.
- **Secret Manager**: Billed by active secret versions (1 version) and secret access operations (executed only during instance cold starts, ~200 accesses/month).
- **Vertex AI Gemini**: Billed per token processed by `gemini-3.8-flash` (~800 input tokens and ~200 output tokens per summarize call, estimated at 300 calls/month).
- **Network**: Egress bandwidth for HTML/JS assets, API responses, and zip exports (~15 KB average per web request).

## Operations and Observability

- **Health Checks & Probes**: Dedicated `/api/health` route responds with HTTP 200 `{ status: "ok" }`. Configured on Cloud Run as both startup probe (checks every 5s after 2s delay, failing after 6 attempts) and liveness probe (checks every 15s, failing after 3 attempts).
- **Logging**: All Express application logs (`console.log`, `console.error`) and unhandled exceptions are captured automatically in Cloud Logging with structured severity levels and revision attribution.
- **Metrics**: Standard Cloud Run metrics in Cloud Monitoring track request count, request latencies (p50, p95, p99), instance counts, CPU utilization, and container memory utilization.
- **Budget Alert Recommendation**: Because budget alerts require billing account permissions outside the scope of Terraform pipelines, project administrators should establish a Cloud Billing budget alert for project `vibe2prod-509620` at the billing account level with thresholds at 50%, 80%, and 100% of expected monthly spend.

## Rollout

1. **Prerequisites & Secrets Generation**: Terraform creates `random_password.app-vibed-app-5-admin-token-secret`, `google_secret_manager_secret.app-vibed-app-5-admin-token`, and `google_secret_manager_secret_version.app-vibed-app-5-admin-token-version`.
2. **State & Storage Infrastructure**: Terraform provisions `google_firestore_database.app-vibed-app-5` in `us-central1` and `google_storage_bucket.app-vibed-app-5-uploads` with 30-day lifecycle deletion rules.
3. **IAM Bindings**: Terraform applies resource-level IAM bindings (`roles/secretmanager.secretAccessor` on the secret, `roles/storage.objectViewer` and `roles/storage.objectCreator` on the bucket) and the conditioned project binding (`roles/datastore.user` conditioned on `app-vibed-app-5`).
4. **Service Deployment**: Terraform applies `google_cloud_run_v2_service.app-vibed-app-5` using the container image provided by `var.image`, mounting environment variables and the secret version.
5. **Post-Deployment Verification**:
   - Verify `GET /api/health` returns `{"status":"ok"}`.
   - Verify `POST /api/notes` writes a note and `GET /api/notes` retrieves it from Firestore.
   - Verify `POST /api/summarize` produces an AI summary via Vertex AI.
   - Verify `POST /api/upload`, `GET /api/files/:name`, and `GET /api/export` interact with Cloud Storage correctly.
   - Verify `DELETE /api/notes/:id` rejects requests without the admin token and accepts requests with the valid `x-admin-token` header.

## Risks

- **Cold Start Latency**: With `min_instance_count = 0`, initial requests after idle periods may experience a cold start. Mitigated by `startup_cpu_boost = true` and a lightweight health check probe.
- **Export Archive Memory Consumption**: `GET /api/export` downloads files into memory to build a zip buffer. If storage accumulates many large files, memory usage could spike. Mitigated by the 5MB upload limit per file, 512MiB container memory limit, and 30-day GCS lifecycle expiration.
- **Vertex AI API Quotas**: Bursts of summarization requests could encounter concurrency rate limits. Mitigated by error logging and standard 60-second Cloud Run request timeouts.
- **Public Access**: Public traffic is permitted via `invoker_iam_disabled = true`. While write and summarize actions are accessible to demo users, destructive deletions require the `ADMIN_TOKEN`.

## Required Code Changes

### 1. `package.json`
Add the official Google Cloud client libraries for Firestore and Storage:
```json
"@google-cloud/firestore": "^7.11.0",
"@google-cloud/storage": "^7.15.0"
```

### 2. `server.js`
- **Health Probe Route**: Add `app.get("/api/health", (req, res) => res.status(200).json({ status: "ok" }));` at the top of the route declarations.
- **CORS Configuration**: Replace the strict origin whitelist with `app.use(cors())`:
  ```javascript
  app.use(cors());
  ```
  This prevents HTTP 500 errors caused by throwing an error when the browser's `Origin` header matches the Cloud Run production domain.
- **Vertex AI Client Setup**: Update the `GoogleGenAI` initialization:
  ```javascript
  let ai = null;
  function getAI() {
    if (!ai) {
      ai = new GoogleGenAI({
        vertexai: true,
        project: process.env.GOOGLE_CLOUD_PROJECT || "vibe2prod-509620",
        location: "global",
      });
    }
    return ai;
  }
  ```
  In `app.post("/api/summarize")`, remove the `if (!process.env.GEMINI_API_KEY)` guard.
- **Firestore Notes Integration**:
  ```javascript
  import { Firestore } from "@google-cloud/firestore";
  const firestore = new Firestore({
    projectId: process.env.GOOGLE_CLOUD_PROJECT || "vibe2prod-509620",
    databaseId: process.env.FIRESTORE_DATABASE_ID || "app-vibed-app-5",
  });
  const notesCollection = firestore.collection("notes");
  ```
  Update `GET /api/notes`, `POST /api/notes`, and `DELETE /api/notes/:id` to perform asynchronous reads, writes (`notesCollection.doc(String(note.id)).set(note)`), and deletes (`notesCollection.doc(String(id)).delete()`).
- **Cloud Storage Uploads & Export**:
  ```javascript
  import { Storage } from "@google-cloud/storage";
  const storageClient = new Storage({
    projectId: process.env.GOOGLE_CLOUD_PROJECT || "vibe2prod-509620",
  });
  const bucket = storageClient.bucket(process.env.GCS_BUCKET_NAME || "app-vibed-app-5-uploads");
  ```
  Switch Multer storage to `multer.memoryStorage()`. Update `POST /api/upload` to upload `req.file.buffer` to `bucket.file(filename)`. Update `GET /api/files/:name` to stream from `bucket.file(reqName).createReadStream()`. Update `GET /api/export` to download bucket objects and assemble the zip archive using `AdmZip`.
